# Сортировка подсчетом
## Описание алгоритма
Алгоритм работает без сравнения элементов между собой. На первом этапе определяется диапазон значений в массиве — находятся минимальный ($\text{min\_k}$) и максимальный ($\text{max\_k}$) элементы. Затем выделяется вспомогательный массив частот `array_count` размером $k = \text{max\_k} - \text{min\_k} + 1$, инициализированный нулями.

В процессе работы алгоритм:
1. Вычисляет частоту появления каждого числа, смещая значения на $-\text{min\_k}$ (что позволяет корректно обрабатывать и отрицательные числа).
2. Последовательно перезаписывает исходный массив `array`, разворачивая значения из массива частот с учетом смещения $+\text{min\_k}$.

*(Примечание: данная реализация является простейшей модификацией сортировки подсчетом, работающей «на месте» с затиранием исходных элементов, поэтому она не сохраняет устойчивость/стабильность для сложных структур данных).*

## Временная сложность
* **Временная сложность:** $O(n + k)$, где $n$ — размер массива, $k = \text{max\_k} - \text{min\_k} + 1$ (размах значений).
* **Пространственная сложность:** $O(k)$ дополнительной памяти под массив `array_count`.

## В каких случаях применять
1. Диапазон значений $k$ мал по сравнению с количеством элементов $n$ ($k \le n$).
2. Массив состоит из целых чисел (или элементов, легко маппящихся в целые числа).
3. Требуется гарантированное линейное время выполнения $O(n)$ независимо от первоначального порядка элементов.

## Тестирование
Тестирование происходит для трех случаев: 
- **Хороший** (массив отсортирован);
- **Плохой** (массив отсортирован в обратном порядке)
- **Случайный** (массив со случайно упорядоченной последовательностью)

> **Важно:** Результаты времени зависят от диапазона $k$. Ниже приведены замеры для $n = 100\,000$ при диапазоне значений $k \approx n$:

| Случай | Размер ($n$) | Диапазон ($k$) | Время (сек) |
| :--- | :--- | :--- | :--- |
| `Хороший` | 100000 | 100000 | 0.000164 |
| `Плохой` | 100000 | 100000 | 0.001711 |
| `Случайный` | 100000 | 100000 | 0.002431 |

## Объяснение результатов тестирования
В отличие от алгоритмов, основанных на сравнениях (вставка, пузырек, быстрая сортировка), времени выполнения Counting Sort **практически безразличен исходный порядок элементов**:

1. **Идентичность проходов:** Во всех трех случаях («хорошем», «плохом» и «случайном») алгоритм всегда выполняет одинаковое количество шагов:
   * Однократный проход по массиву $n$ для поиска $\text{min}$ и $\text{max}$.
   * Однократный проход по массиву $n$ для заполнения частот.
   * Полный проход по массиву частот $k$ и перезапись $n$ элементов обратно в `array`.
   
2. **Линейная скорость:** Время выполнения для всех трех случаев будет одинаково близким к $O(n + k)$, опережая сортировки $O(n^2)$ на несколько порядков. Незначительные отклонения могут возникать только из-за кэш-промахов процессора или особенностей предсказателя переходов (branch predictor) при случайном распределении данных.
